# 關卡四：模糊地帶清理

# 任務交接檢查清單

------

## 📚 什麼是 Definition of Done (DoD)？

DoD 定義
**Definition of Done (完成定義)** 是一組明確的標準，用來判斷一個任務是否「真正完成」。

**為什麼需要 DoD？**

- 避免「我以為做完了」的誤解
- 確保交付品質一致
- 減少返工與修改
- 讓交接更順暢

**好的 DoD 特徵：**
✓ 具體可衡量
✓ 可驗證
✓ 團隊共識
✓ 合理可達成

------

## 各任務 Definition of Done 範例

### 1️⃣ 技術設計文件 DoD

**檢查清單：**

- [ ] 系統架構圖已繪製
- [ ] API 規格文件已完成（包含端點、參數、回應格式）
- [ ] 資料庫 Schema 已定義（ER Diagram）
- [ ] 安全性考量已評估（認證、授權、資料加密）
- [ ] 效能指標已設定（回應時間、併發量）
- [ ] Tech Lead 已審核並簽核

**品質標準：**

- 文件清晰易懂，新成員可理解
- 技術決策有明確理由說明
- 包含替代方案評估

------

### 2️⃣ 後端 API 開發 DoD

**檢查清單：**

- [ ] 程式碼已提交至 Git 並通過 CI/CD
- [ ] 單元測試覆蓋率 ≥ 80%
- [ ] 整合測試已撰寫並通過
- [ ] API 文件已更新（Swagger/OpenAPI）
- [ ] Code Review 已完成（至少 1 位 Reviewer 核准）
- [ ] 無 Critical 或 High 優先級 Bug
- [ ] 效能測試達標（回應時間 < 3 秒）

**品質標準：**

- 程式碼符合團隊 Coding Style
- 錯誤處理完善
- 日誌記錄完整

------

### 3️⃣ 前端介面開發 DoD

**檢查清單：**

- [ ] UI/UX 與設計稿一致（設計師簽核）
- [ ] 響應式設計已實作（測試 Desktop/Tablet/Mobile）
- [ ] 無障礙標準已達成（WCAG AA 級）
- [ ] 跨瀏覽器測試已完成（Chrome, Firefox, Safari, Edge）
- [ ] 前端單元測試覆蓋率 ≥ 70%
- [ ] 效能指標符合要求（First Contentful Paint < 2s）
- [ ] 無 Console Error 或 Warning

**品質標準：**

- 使用者體驗流暢
- 載入效能優異
- 視覺呈現專業

------

### 4️⃣ 測試驗證 DoD

**檢查清單：**

- [ ] 測試案例已撰寫（涵蓋所有 AC）
- [ ] 自動化測試已執行並全數通過
- [ ] 手動測試已完成（Happy Path & Edge Cases）
- [ ] 回歸測試已通過（確保無功能退化）
- [ ] 測試報告已產出（包含測試覆蓋率、Bug 統計）
- [ ] 所有 Bug 已修復或延後處理（經 PO 同意）

**品質標準：**

- 測試案例完整涵蓋需求
- 發現的 Bug 都有追蹤
- 測試資料真實有效

------

## 📝 下一步

1. 閱讀並理解 DoD 的概念
2. 前往 Jira 關卡四：模糊地帶清理 之下新增一張 child work item(子系工作項目)
   1. Summary/標題: **[ 完成各子任務的 DoD ]**  
3. 系統將會自動開立子任務
4. 打開每個子任務內的描述加上 DoD 檢查清單
5. 完成後將每個子任務移動至 **Done (完成)**

------

🔐 密碼提示
完成任務並將 child work item(子系工作項目) 移動至 **Done(完成)** 後，關卡四：模糊地帶清理 的密碼欄位將自動出現密碼碎片。
